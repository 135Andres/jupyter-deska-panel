# Notebook fixtures

Small, synthetic Jupyter notebooks for the panel's tests. Every file here was
written by hand for this repository (MIT, see `LICENSE`): none was downloaded
from the internet, and none comes from a real person's work.

| File | What it holds |
| --- | --- |
| `demo-sales.ipynb` | The showcase notebook (README, walkthroughs, screenshots): Markdown with LaTeX, a pandas table, a PNG bar chart drawn on a canvas, an SVG line chart, stdout and stderr streams, an ANSI traceback and VS Code execution timings. Generated by `npm run demo-notebook`; every number is made up. |
| `rich-outputs.ipynb` | A pandas table in `text/html`, a matplotlib `image/png`, an `image/svg+xml`, and a Markdown cell with inline and display LaTeX. The PNG is a real 2×2 image; the SVG has no script. |
| `stream-and-traceback.ipynb` | A stdout stream, a stderr stream, and an error output whose traceback carries real ANSI escape sequences (`\u001b[0;31m` and friends). |
| `plotly-with-fallback.ipynb` | A Plotly output (`application/vnd.plotly.v1+json`) that also carries `image/png`, so the panel can show the static fallback. |
| `plotly-no-fallback.ipynb` | A Plotly output with no `image/png`, only `text/plain`, so the panel shows its placeholder row. |
| `nbformat3.ipynb` | A valid nbformat 3 notebook, with a `worksheets` list, to check the "older notebook format" path. |
| `invalid-json.ipynb` | Truncated JSON, to check the invalid-input path. |
| `jupytext-percent.py` | A Jupytext percent script: YAML header, a Markdown cell with LaTeX, two code cells (one with `tags`) and a raw cell. |
| `databricks-source.py` | A Databricks source export: `# MAGIC %md`, a `# DBTITLE` line, a `%sql` cell and a `%pip` cell. |
| `marimo-app.py` | A marimo app: a named cell, an `mo.md(...)` cell and cells with a trailing `return`. |
| `rmarkdown-report.Rmd` | R Markdown with YAML front matter, `{r setup, include=FALSE}`, `{r means}` and `{python}` chunks, and a four-backtick fence that holds a ` ```{r} ` example which is not a chunk. |
| `quarto-doc.qmd` | Quarto with `#\|` chunk options, a `{python}` and an `{r}` chunk, and a callout. |
| `zeppelin-note.zpln` | A Zeppelin note: a `%md` paragraph, `%spark.pyspark` text, a `%sql` TABLE result, a `%python` IMG result and a `%spark` ERROR. |
| `colab-like.ipynb` | A notebook the way Google Colab saves them: nbformat 4.0 (no cell ids), `metadata.colab`, `executionInfo` run times, outputs with metadata, and a chart pasted into Markdown as an `attachment:`. |
| `kaggle-like.ipynb` | A Kaggle kernel: `_uuid` metadata, execution timestamps, an `execute_result` table. |
| `vscode-like.ipynb` | A VS Code notebook: `metadata.vscode`, execution timestamps and an ANSI traceback. |
| `jupyterlab-like.ipynb` | A JupyterLab notebook: an `execute_result` with `image/png` + `text/plain`, a Markdown `attachment:`, and an ANSI traceback. |
| `generate.ts` | The generator for the notebooks too large to commit. |

Every valid `.ipynb` here follows the public nbformat specification
(<https://nbformat.readthedocs.io/>); most are nbformat 4.5, and the
`*-like.ipynb` files copy the exact versions and metadata quirks of the tools
that saved them (Colab writes 4.0, Kaggle 4.4). Hostile notebooks live in
`fixtures/hostile/`, not here.

## Using the generator

`generate.ts` is TypeScript and runs from the Vitest tests. It never writes to
disk and has no dependencies:

```ts
import {
  generateLargeNotebook,
  generateMixedNotebook,
} from '../../fixtures/notebooks/generate'

const mixed = generateMixedNotebook() // 10,000 cells, Uint8Array
const large = generateLargeNotebook() // over 50 MiB, Uint8Array
```

Both are deterministic: the same parameters give the same bytes. `mixed` mixes
Markdown and code cells, and the code cells carry stream, text and HTML outputs.
`large` repeats a fixed text block until the JSON passes 50 MiB, so no large
file is committed. A caller that needs a file writes the bytes to the system
temporary directory (`os.tmpdir()`), never inside the repository.

`src/adapters/fixtures.test.ts` reads the `.ipynb` files with Vite's `?raw`
imports and exercises the generator.
